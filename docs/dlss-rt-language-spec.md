# 更新官方 DLSS 超分 DLL 并增加 NVIDIA 硬件光追与语言包框架

## Problem Statement

玩家希望在现有 Windows DOOM 移植版中使用最新 NVIDIA 超分运行库，获得基础硬件光追及反射，并能通过外部语言包替换游戏文字。

项目已经集成 NGX Super Resolution，但固定使用旧 SDK、固定输入与输出尺寸，并将多个技术路径以 DLSS 版本命名。现有下载脚本只要找到头文件便认为安装完成，不能可靠升级；递归选取第一个同名 DLL，也无法保证选择正确架构和发布构建。玩家难以确认实际使用了哪个运行库、哪个功能以及失败后的显示路径。

现有 Ray Reconstruction 输入包含合成材质数据，尚没有提供阴影和反射所需的场景几何与光追照明。文字则由编译期字符串和菜单图片提供，外部文本文件本身不能完成运行时语言切换。

## Solution

优先完成可复现的 NVIDIA 官方超分运行库升级与部署，准确显示其实际版本与运行状态；随后在 NVIDIA RTX 上通过 DXR 提供点光源阴影和选定表面的单次反射，最后与超分组合显示。外部语言包框架独立推进，首版提供启动语言选择、稳定文本键与英文回退。

玩家通过游戏内“选项 → 图形设置”分别控制光追（RT）、官方超分（SR）和项目的 DLSS5／DLSSNR 神经渲染增强（NR）。三个请求分别保存，菜单分别显示当前实际状态及不可用或回退原因；正常支持的开关在游戏运行中生效，并保存到下次启动。项目已有模式名称保留；SR、DLAA 与 NR 的实际执行证据分别记录。

官方最新版本以实施时核验的稳定发布为准，核验后固定版本和来源。本次规格查到的 NVIDIA 官方最新发布为 DLSS SDK `v310.9.1`，发布于 2026-09-08；当前项目固定为 `v310.7.0`。SDK 发布号、DLL 文件版本、超分预设和产品功能分别记录，不能用“DLSS 5”名称推断 DLL 提供的功能。

用户将提供带独立显卡机器的 SSH 访问，用于构建、执行与画面验收。首个实施里程碑是官方 DLL 更新，DXR 和语言框架作为后续里程碑；本规格不等于功能已经实现。

## Implementation Decisions

- 交付顺序采用官方 DLL 更新、帧输入与分层、语言框架、DXR 阴影、DXR 反射、RT 与 SR 组合。语言框架可独立推进。
- 继续使用现有 NGX 集成，扩展依赖下载、版本识别、部署和回退；首轮不重写完整渲染器。
- 实施前重新核验 NVIDIA 官方稳定发布，固定所选 tag 和 commit。将版本、来源、架构、文件摘要、文件版本和校验结果写入安装元数据。文件摘要用于完整性与复现，来源及可用签名检查分别建立信任。
- 明确选择 Windows x64 的 Release 超分运行库，不依赖递归扫描后的第一个文件。SR、RR、帧生成的运行库分别按实际功能部署；首个里程碑不为帧生成增加 DLL。
- 下载、解包、校验在临时安装区完成，全部成功后才发布新安装。旧 SDK、依赖库及已部署 DLL 作为一致版本保留备份，提供恢复操作；游戏使用 DLL 时不强行覆盖。
- 是否已经安装以完整性和版本元数据判断，不能仅检查一个头文件。相同版本且通过校验可复用缓存；旧版或不完整安装应明确更新。
- 更新后程序报告实际加载运行库的版本及所启用功能。第三方 Swapper / RenoDX 路径保持可区分状态，不能因同名文件夹或单纯替换 SR DLL 宣称启用了 DLSS 5 的所有功能。
- 帧输入使用一致的尺寸、相机采样、jitter、实际帧间隔和 reset 契约。运动矢量方向为当前像素到上一帧像素，明确 jitter 的处理；固定 demo 导出保留游戏时间线。
- 相机传送、换关、读档、场景类型变化和渲染配置变化按规则清除历史。动态扇区变化需要相应运动数据或历史失效处理。
- 首版保留 320×200 场景与 1280×800 显示。先查询并验证 NGX 是否接受此输入；不支持时记录原因并回退。可变场景分辨率和完整 Quality / Balanced / Performance 档位属于后续扩展。
- 补充表面类别、材质标识、未照明 albedo 和有效场景遮罩；将武器与二维 UI 从光追重建和超分输入中分层。不要通过修改全局 UI 分辨率实现质量档位。
- DXR 与 NGX 分别检测并启用；明确选择实际渲染适配器，记录驱动与能力。建议采用 DXR 1.1 inline ray tracing，检查 Shader Model 6.5 并增加 DXC 构建支持。
- 软件主视图提供主表面，新增场景提取模块提供屏幕外地图几何、纹理和材质；DXR 模块完成阴影、单次反射、过滤及合成。必要时新模块采用 C++，保留面向原 C 游戏的窄接口。
- 场景提取覆盖墙、地板、天花板和 masked 表面；BSP 区域裁剪后再三角化。正确处理天空、透明、纹理偏移、坐标转换和绕序。
- 静态几何构建 BLAS，动态扇区按受影响几何更新或重建并同步 TLAS。门和地板高度变化同时更新相关邻接墙面；旧地图释放前卸载场景。
- 资源所有权、barrier、队列同步和 GPU 使用结束后的释放集中在渲染模块内，调用者只提供场景与本帧输入并接收输出和状态。
- 材质配置按纹理名称匹配，默认关闭多数表面反射。灯光先提供显式点光源；扇区亮度可作为环境基线，不能当作具有位置的灯光。
- 新照明在线性色彩空间计算，明确原版亮度、gamma 和调色板效果的合成规则。当前最终屏幕颜色不能直接当作未照明材质颜色重复照明。
- 单次反射从场景几何命中后根据纹理 UV 与基础照明着色，miss 使用环境颜色；首版反射地图及动态门、平台。先提供硬阴影与稳定低粗糙度反射，随机效果须先具备可靠过滤。
- RT 合成发生在 SR 之前。SR 失败的回退路径继续使用合成后的颜色；RT 失败可关闭 RT 并进入普通路径。各阶段给出可诊断的失败原因。
- 游戏内“选项 → 图形设置”必须提供三个明确的开关：光追（RT）、超分（官方 DLSS SR）和神经渲染增强（DLSS5／DLSSNR，NR）；使用原菜单键盘操作、返回和关闭行为，不能仅提供命令行参数或要求手工编辑配置。RT 总开关控制本规格的阴影与已配置材质反射，诊断视图不等同于游戏光追开关。
- RT、SR、NR 分别表达用户请求并保存偏好。RT 与 SR 支持两者关闭、仅 SR、仅 RT 和 RT 加 SR；NR 开关请求项目已有的 DLSS5／DLSSNR 神经渲染增强，关闭 NR 不改写 RT 或 SR 请求。DLSS5／DLSSNR 是项目的 NR 模式身份，不定义为超分或 SR 加 DLAA；SR 或 DLAA 执行成功不能作为 NR 已启用的证据。
- NR 与 SR 的可运行组合由具体后端契约及实际验证决定，不把“SR 关闭必然关闭 NR”作为通用语义。关闭 SR 时仅停止 SR；若当前 NR 后端确实需要 SR 或其他已验证依赖，保留 NR 请求，明确显示该组合不支持及原因。其他组合分别尝试和记录实际状态；缺少 NR 后端或创建／执行失败时关闭实际 NR，保留成功的 RT／SR 或普通显示，不能把 DLL 文件存在、用户选择“开”或其他 NGX 功能成功当作 NR 激活。
- 菜单分别展示 RT／SR／NR 用户期望的开关值与实际状态（启用、关闭、不可用、未验证或回退）。DXR、官方 SR 与实际 NR 后端依赖分别判断，状态包含可追溯的能力、后端加载、功能激活和执行结果；不可用项仍可查看原因，一个功能不可用不阻止其他可用功能。可选扩展如只能在启动时加载，菜单明确提示需要重启，不在切换时安装或注入组件。
- 已支持的 RT／SR／NR 功能开关在同一进程内安全生效：在帧边界切换并等待必要的 GPU 使用结束，清除相关历史；反复关闭再打开可重新检查并初始化功能。切换失败保留已成功合成的可显示路径。历史重置继续遵循动态几何及反射规则。
- 图形偏好保存到现有用户配置，优先级为明确的启动参数、已保存偏好、当前模式默认值；启动参数覆盖只影响本次有效值，退出时不自动覆盖保存偏好。菜单主动修改则保存新偏好并在本次使用；语言选择仍按原规则重启生效。
- 语言框架使用有 schema 版本的受限 UTF-8 INI、稳定文本键、内建英文目录、缺键回退及整体解析成功后发布。限制输入大小与长度并校验编码、重复键和版本。
- 语言优先级为启动参数、已保存偏好、英文。首版在启动时加载，切换后重启；字符串保持只读且在语言模块存活期间有效。
- 逐处迁移文本消费者，保留依赖静态初始化和字面量拼接的英文定义。模板参数使用受限替换与参数校验，不把外部文本当任意格式串执行。
- 首批消费者覆盖退出、选项、拾取及新增图形设置提示。菜单图片通过明确的文字入口逐步迁移；先用原字体可显示字符的示例包验收。
- UTF-8 文件支持与 Unicode 字形显示分别处理。预留字体标识和绘制接口，首版说明缺字限制；长文本安全换行或截断，不逐字节大写化 UTF-8。

## Testing Decisions

- 主要 seam 使用现有“启动程序 → 固定 demo 回放 → 日志与 PNG 导出”的完整可观察行为。用户补充的验收方式为提供独显机器 SSH，由 agent 执行实机验证；不引入用于测试的第二套渲染入口。
- 好的测试检查玩家可见结果、实际运行状态和失败后的可用性，不检查私有函数名称、内部调用顺序或照抄实现分支。
- 既有先例是 demo 播放、颜色 / 深度 / 法线 / 速度调试视图、单模式 PNG 导出和逐模式回放。仓库目前未发现这些新功能的自动测试套件，不能据此宣称已有覆盖。
- 官方 DLL 更新通过真实下载 / 部署入口在隔离目录验收：首次安装、旧版升级、相同版本复用、损坏缓存、网络中断、架构选择、发布构建选择、正在使用的 DLL 和备份恢复。检查实际部署文件及元数据，并启动程序确认加载版本。
- 下载与部署失败必须留下可启动的旧版本，不能只检查进程报错。恢复测试确认 DLL 和 SDK 依赖作为同一版本恢复。
- SR 测试覆盖已支持 RTX、不可用能力、初始化 / 创建 / 执行失败、关闭 SR、静止、移动、快速转身、传送、换关、读档及菜单切换。检查最终画面和实际路径日志。
- DXR 阴影测试使用位置已知的点光源与墙体，覆盖闭合区域、透明栅栏、天空、门开关、平台移动和邻接墙面更新。
- DXR 反射测试将目标几何放在主视图之外，确认选定反射表面仍能显示目标；检查材质开关、动态几何及预算限制。首版不要求 sprite 出现在反射中。
- 组合测试至少覆盖原版、SR、RT 阴影、RT 阴影加反射、RT 加 SR、RT 不可用及 SR 失败。SR 失败后应保留成功的 RT 合成结果。
- 菜单验收通过真实游戏键盘操作进入“选项 → 图形设置”，分别切换 RT／SR／NR 并返回游戏，检查实际画面、菜单状态和日志一致。覆盖 RT／SR 四种组合以及各组合下的 NR 请求关闭／开启、SR 关闭而 NR 请求保留、实际后端支持或拒绝组合的原因、重新启用、连续切换及历史重置，不能只用启动参数替代菜单操作。NR 验收需实际后端激活／执行证据，SR、DLAA 成功另行记录。
- 菜单分别覆盖 DXR／SR／NR 后端不支持、缺失运行库或 NR 依赖、初始化／创建／执行失败；确认原因可见、回退真实发生且游戏可继续。NR 后端不可用或尚无实际验证时明确标记，不能伪造加载，也不能以 SR／DLAA 的画面代替 NR 激活证据。
- 菜单修改后退出并重启，验证图形偏好持久化、明确启动参数覆盖及菜单主动修改的优先级。英文与示例语言逐项检查图形菜单、状态、失败原因和长提示；同时确认武器、HUD、菜单位置及最终 PNG 正常。
- UI 测试检查武器、状态栏、菜单与长提示，不将二维像素作为光追表面。导出最终帧应包含用户实际看到的叠加结果。
- 语言包通过启动选择和实际提示验证外部替换、持久化与英文回退。解析和模板替换的异常输入可通过其模块公开接口补充测试，包括非法 UTF-8、重复键、超长值、版本不匹配和参数错误；不模拟内部解析步骤。
- 使用用户提供的独显机器 SSH 前读取 runner 配置，确认 GPU、驱动、Windows 工具链、IWAD、demo 和交互桌面。SSH 命令执行成功、编译成功及正确画面分别验收；无交互桌面时明确留下画面验收未完成的结论。
- 实机证据包含运行版本、能力日志、关键帧对比、GPU 分阶段耗时与显存记录。不同 GPU / DLL 版本不强求逐像素一致，不预先承诺帧率或画质提升幅度。
